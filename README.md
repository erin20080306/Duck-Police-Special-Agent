# 鴨警特工 · Duck Force

以 Three.js 製作的第一人稱單人戰術射擊遊戲。場景參考使用者提供的 Astral War 錄影（IRON DOME 的鋼架棚頂與 SHOGUN 的雨夜聚落），朝灰暗工業廢墟、鋼架屋頂、濕地與煙雨的氣氛調整；主角保留奶油色絨毛鴨頭、深海軍藍警用長外套與黑色大盤帽，搭配白襯衫、黑領帶、金色徽章及鍊飾、青藍發光模組，敵人改為三種喪屍。目前共三張戰區。

角色與建築是程式化幾何搭配材質的風格化近似，並非參考影片或人物圖片的精確重建。目前沒有匯入 Blender 雕刻模型、動作捕捉或真人多人連線。

## 場景與戰鬥

- **鋼鐵廢墟**：破損弧形鋼架棚頂、分層工業天際線、吊車、水塔、屋頂通風設備、管線、碎裂女兒牆與隔離標示。保留貨櫃、裝甲運輸車、沙包及路障形成的通行路線。
- **雨夜神社**：鳥居、瓦頂、石燈籠、庭院與枯樹，加入地面薄霧、雨線、燈暈與濕地光影。
- **霓虹港灣**：暴雨夜的貨櫃碼頭。兩側是可作掩體的堆疊貨櫃（分層錯位、色帶區分），中段有拱形鋼桁架轉運棚與跨街輸送帶天橋，地面有吊車軌道、繫船柱與垂掛纜繩，北側是兩座跨越主道的門式起重機吊掛區，南側是靠泊船體、舷梯與撤離停機環，遠景為貨櫃碼頭天際線。夜空著色器另有港區燈光反照的雲底。
- **戰場效果**：陰雲天空、煙囪與排氣口蒸汽、細雨、積水與流動光紋；射擊包含槍口火光、煙霧、彈殼、命中塵屑與死亡效果。環境與戰鬥粒子數量都有上限。
- **三種喪屍**：感染工人靠近後近戰；狂奔喪屍快速追擊；狙擊喪屍以紅色瞄準線預警後射擊。AI 依掩體判斷視線並尋路，玩家可用蹲姿躲在低掩體後。
- **武器與任務**：AR-07 突擊步槍、P-09 戰術手槍，支援瞄準、後座力、換彈與切槍。三種難度、三波清剿、行動倒數、有限彈藥、波次補給、命中判定與結算。

特工技能為**脈衝護盾**：按 Q 或手機技能鍵，對 10 個場景單位內且未被掩體阻擋的喪屍造成 55 傷害並暈眩 2.4 秒，同時獲得 4 秒護盾，減少 75% 傷害；冷卻 18 秒。技能狀態與冷卻顯示於 HUD。

### 手機瞄準與方向操控

參考市面手機射擊遊戲（主機／手機 FPS 的 aim assist 拆成「轉向阻尼」與「吸附」兩層；CoD Mobile 類的陀螺儀多以「僅瞄準時」為預設）後新增下列機制，全部只在觸控裝置生效，滑鼠操作不受影響：

- **輔助瞄準（`src/aim-assist.js`）**：準星進入未被掩體遮擋的目標的外圈時，同一段滑動轉過的角度變小（轉向阻尼），越靠近中心越明顯；內圈再加上輕微吸附。吸附強度乘上你當下的滑動速度，**手不動時吸附為零**，不會自己瞄準；單幀最多只補完剩餘角度的一半。可選關閉／標準／強化。準星鎖定目標時會轉為琥珀色並出現圓環。
- **開鏡吸附**：按下瞄準鍵時，若外圈內已有未被遮擋的目標，0.18 秒內平滑帶向該目標，之後即恢復手動。
- **陀螺儀瞄準（`src/gyro.js`）**：關閉／僅瞄準時／全時三段，另有獨立靈敏度。採相對量測（第一筆只取基準），橫向時自動把 pitch 換到對應的裝置軸；低於門檻的抖動會被丟棄，暫停或切換分頁後重新取基準，避免回來時瞬間甩鏡。iOS 需在設定頁按鈕授權動作感測器。
- **滑動曲線**：快滑轉得更快、慢滑保留精度（上限 1.85 倍），瞄準時大幅降低此加速；瞄準區的旋轉需超過 3 px 才開始，避免點擊帶偏準星。
- **輕點射擊**：在右側瞄準區短暫輕點即射一發，右手不必移到開火鍵。被系統中斷（pointercancel／失去指標）的觸控不會誤射。
- **開鏡靈敏度**：與腰射靈敏度分開調整。
- **轉向死區**：左側單指轉向加入死區，往前跑時的手指偏移不再讓鏡頭慢慢漂走。
- **震動回饋（`src/haptics.js`）**：命中、爆頭、擊殺、受傷與技能各有短振動，可關閉；不支援 Vibration API 的裝置自動略過。

直向與橫向皆有手機配置，橫向可獲得較寬視野。開始時保留使用者的直向／橫向選擇；全螢幕由部署頁按鈕手動啟用。手機預設「輔助射擊」：準星對到沒有掩體遮擋的喪屍時自動開火，可在設定切換為手動射擊。搖桿前推即快跑，瞄準或蹲下時減速，無需另一顆疾跑鍵。左側預設是浮動單指控制：可從任意空白處上滑前進、下滑後退、左右轉向，斜上滑可邊轉邊跑；設定可切換為左右平移。視角使用依時間平滑的跟隨並依螢幕短邊統一靈敏度。左側、右側視角區與操作按鍵分別追蹤觸控指標，支援同時移動、轉向與射擊。切換分頁、失焦或取消觸控時會清除輸入，避免持續移動或開火。

手機自動使用效能配置：降低像素比與環境粒子量、限制局部燈光，關閉動態陰影及桌面後製；手機不建立 PMREM 環境反射。畫面解析度可隨持續的幀時間壓力降低。靜態環境和角色按材質合併幾何，以控制繪製次數；這些限制仍需要真實裝置量測確認效果。

## 安裝到主畫面與離線遊玩

正式版包含 Web App Manifest、應用程式圖示與 Service Worker。首次請保持連線，等待大廳顯示「離線戰區已備妥」；程式會預先快取該次正式建置的頁面、JavaScript、CSS、材質與圖示，之後可離線載入三個戰區。瀏覽器清除網站資料或回收快取後，需要重新連線準備。

- **Android／支援安裝提示的桌面瀏覽器**：在大廳按「安裝到主畫面」，依提示安裝；若尚未提供原生提示，可依畫面說明從瀏覽器選單操作。
- **iPhone／iPad**：使用 Safari 開啟網站，按「分享」→「加入主畫面」→「新增」。若系統顯示「以網頁 App 開啟」，請保持開啟。安裝後從主畫面圖示啟動。[Apple 操作說明](https://support.apple.com/en-ae/guide/iphone/iphea86e5236/ios)
- **更新**：新版本完成快取後，大廳會顯示「套用遊戲更新」。按下後才重新載入；遊戲進行中不主動重新整理。

正式部署需使用 HTTPS；本機 `localhost` 或 `127.0.0.1` 可用於開發測試。安裝入口、全螢幕與主畫面啟動方式由瀏覽器／作業系統支援情況決定。[MDN：PWA 安裝條件](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable)

`npm run dev` 不註冊 Service Worker，以免快取干擾開發。請用下方的正式建置預覽驗證安裝與離線功能。

## 本機開發

需要 Node.js 22.12 以上：

```sh
npm run dev
```

執行自動測試及正式建置：

## 驗證範圍

自動測試涵蓋視線與掩體、移動防穿牆、彈藥守恆、尋路、三張地圖的出生點與路線、喪屍幾何及動畫節點、脈衝範圍／掩體阻擋、護盾減傷、環境資源釋放與手機場景預算。PWA 測試涵蓋完整建置快取、離線導覽、更新版本保留、快取作用域、圖示尺寸及安裝提示流程。

本輪已在 Chromium 瀏覽器檢查桌面及 390×844、844×390、568×320 手機版面，驗證單點射擊、準星輔助射擊、轉向、單指移動、技能及暫停。停止正式版伺服器後重新載入並切換神社／使用技能成功，驗證遊戲本體可從 Service Worker 快取離線啟動。

新增的三張戰區、輔助瞄準與滑動曲線已在 375×812 的 Chromium 觸控模擬中實測：可切換並開始霓虹港灣、行走主道與吊掛區、準星鎖定時 HUD 轉為琥珀色、轉向阻尼實際生效（快照顯示 `assist.friction < 1`）。

擴大後的行走範圍也在同一模擬中逐區檢視：三張地圖的外環道、北端與南端都會渲染出該有的地標與路標，HUD 分區名稱正確。檢視時使用 `npm run dev` 才有的 `window.__duckDebug.teleport()`（正式建置不含此程式碼）；**實際步行穿越全圖、以及放大後的長時間效能與溫度，仍未在真實裝置上量測。****陀螺儀與震動回饋只有單元測試與程式邏輯驗證，尚未在真實 iPhone／Android 上量測；輔助瞄準的手感參數也未經實機試玩調校。** 一併沿用原有結論：**尚未完成真實裝置的觸控、安裝、離線與持續效能驗證，不宣稱手機穩定 60 FPS。** Node 測試中的 DOM／Service Worker 模擬不代表作業系統已實際安裝成功。

發佈前的瀏覽器與實機確認項目：

1. 三個戰區可開始、暫停、繼續、返回大廳；三種喪屍可正常攻擊，狙擊預警、掩體與技能冷卻符合畫面提示。
2. 直向及橫向介面不遮住主要按鍵；同時移動、滑動轉向、開火和施放技能，放開或中斷觸控後輸入確實停止。
   1b. 新的外環道與兩個端區：閘口與連絡道可通行，端區的掩體與地標能辨識方向，HUD 分區名稱與實際位置相符，喪屍會從外圍出生並找到路徑接近。
   2b. 三段輔助瞄準的手感：關閉時完全手動，標準時能穩住準星但不會被拉走，強化時不至於黏在錯誤目標上；輕點射擊不會誤觸；iOS 授權後陀螺儀方向與靈敏度正確，橫向時 pitch 軸沒有互換錯誤。
3. 正式版等待離線備妥後切斷網路，再重新開啟並切換三個戰區；確認材質、武器、音效與 UI 均可用。
4. 安裝到 Android／iOS 主畫面後重新啟動；檢查安全邊界、旋轉、背景切換、更新提示及長時間遊玩的溫度與幀時間。

## 素材與技術

Three.js 採 MIT 授權。音效由 Web Audio 在本機合成，字型使用裝置可用字型與系統備援；遊戲不依賴外部字型下載。

混凝土材質 `public/assets/concrete.webp` 使用內建 imagegen 生成並儲存為 WebP。原始提示詞：photorealistic worn gray industrial concrete surface texture; flat orthographic material scan; fine grain, hairline cracks, damp stains, chipped flecks; neutral gray, flat diffuse lighting, no objects/text/logos. 提示要求可平鋪，邊界連續性未作像素級驗證。

### 擴大戰區

三張地圖的可行走邊界為 **92 × 164** 個場景單位（初版 40 × 72，前一版 64 × 120，本版再擴大約一倍面積），全部連通、沒有分段載入。

- **外環道**：原本 x = ±33 的側牆改成分段路障，留下三個閘口與南北兩端開口，通往新的外環道（x = ±39.5，全長 162）。閘口有橫向連絡道，等於在原街區外再繞一圈，可用來包抄或脫離。
- **北端與南端**：越過原本的北／南廣場再往外，各多一個端區——鋼鐵廢墟是**鐵道場**（軌道、兩節料斗車、裝卸坡道、號誌鋼架）與**車輛場**（拖車列、雨棚檢查哨、路障）；雨夜神社是**石佛林**（石塔、石燈籠、參道石板）與**水庭**（淺池、平板棧道、紅欄杆、水榭）；霓虹港灣是**乾塢**（階梯式塢壁、船段、維修鋼架）與**油庫**（儲油罐群、拖船碼頭）。
- **外環內容**：鋼鐵廢墟是儲油罐群、預鑄板堆與變電站；雨夜神社是夯土牆、竹林與小鳥居；霓虹港灣是冷藏櫃列、報關棚與繫船柱。都有實體碰撞，不是背景貼圖。
- **分區與出生點**：分區由 5 個增為 **9 個**（`sectorFor()`），HUD 依所在位置顯示；喪屍出生點由 14 個增為 **20 個**，其中 6 個位於外環與兩個端區，波次會實際用到新地形。
- **指路**：所有告示牌合併成單一 atlas 貼圖與單次繪製，因此可以自由增加路標而不增加繪製批次；反而讓三張地圖的批次數從 20–23 降到 15–18。

配套修正：

- 原本放在舊邊界之外的背景建築（鋼鐵廢墟的高架平台、塔樓、水塔，霓虹港灣的遠景吊車與貨櫃場）現在落在可行走範圍內，會變成「看得到卻穿得過去」的假牆，已全部移到新圍牆之外。雨夜神社的拱橋改為平舖棧道（遊戲沒有垂直移動，拱起的橋面必然被穿過），乾塢階梯補上碰撞。
- 新增自動測試會在整個可行走範圍上取樣，找出「腳下沒有碰撞、頭上與胸口卻都有實體面」的格子，也就是穿模假牆；三張地圖目前為 0。
- 尋路的搜尋上限改為由 `BOUNDS` 推導，並記住已判定的格子，否則跨越新地圖的長路徑會中途放棄。實測對角線尋路約 1.6–1.9 ms。
- 桌面陰影改為跟隨玩家（對齊整數格避免閃爍），否則固定框在放大後的地圖上不是照不到外圍就是浪費解析度。

效能預算：繪製批次（≤ 24）與動態點光源（≤ 2）維持不變，這兩項才是手機的主要成本；三角形上限由 50k 放寬到 64k，粒子上限由 64 放寬到 80——粒子數量並未增加，只是散布體積跟著地圖變大，單位畫面密度反而下降。
